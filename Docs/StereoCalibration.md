# What is Stereo Calibration?
Stereo Calibration is the initialization process for stereo vision. Similarly to a pair of human eyes, the system takes a set of matching feature points across a pair of images, calculates a mathematical relationship between them, then uses the resulting matrix, called an Essential Matrix, to reconstruct them in 3D space.

## Wait, what are Feature Points?
Feature points are coordinates within an image that represent points of interest, such as sharp changes in pixel colors or corners of objects. These points can be generated by a variety of different algorithms. The best algorithms are ones that find lots of feature points, as this sets up the computer with a better dataset to use for future calculations. 

Three other variables that we needed to take into account come from the physical implementation of the camera: focal length, principal point, and distortion.
The focal length determines how quickly things get larger or smaller as they pull toward or away from the camera. The principal point is how off-center the image will be, due to micro-defects in the camera hardware. The distortion is how warped an image is, and a common example is seeing an image which has a "fish-eye" or rounding effect. This needs to be corrected for, and most computer vision libraries have functionality for countering this. 
 
## Ok, so we have feature points! Now what?

By compensating for the above imperfections, we convert the pixel coordinates into "camera coordinates." However, feature points exist only in the 2D plane. In order to extract a 3D image, we need to have two cameras that are pointed at the same scene from different angles.

The next part of the algorithm is to find the indirect relationship between a point on Camera A and its matching point in Camera B. In short, using its existing information about Point A, it projects a line from Point B, called an epipolar line, which Point A must lie on. The matrix which allows for these calculations is called the Essential Matrix.

## How do I make an Essential Matrix?
There are 2 core components to an Essential Matrix: translation and rotation. Translation is a set of X, Y and Z vector values showing Camera B's position in relation to A's, up to scale. Rotation is how much Camera A is rotated around those 3 axes in respect to Camera B. Combined, they form a 3x3 Matrix. These are difficult to program from scratch, and luckily we were able to use a library
by Eigen called JacobiSVD to create the matrix. Finally, we can check the accuracy of our matrix by comparing matching feature points. The more matches we have, the more accurate our matrix is. 

## How do we get 3D Points from this?
At this point, we can take any point in one camera feed and find its matching point on the other. But we still need to find those points on the Z axis. To do this, we use our existing information to find the positions of the cameras themselves, use them as our "anchors" in 3D, then draw a vector between the two camera centers, from which we can triangulate the depth of each feature point.

## That's a lot of work just to find a set of points!
Indeed, when written like the POC, there's a lot of complicated math that must be explicitly done. But luckily, we don't have to worry about that once we understand the theory. We can simply use the OpenCV library, which drastically cuts down on the amount of work we have to do. This POC's job was simply to teach how the sausage is made. For this use case, we've simply used 2 perspectives of a 3D cube, explicitly marked each feature point, then run the numbers to find the 3D coordinates of each corner.

## Ok, so what's with the output of the 3D points?
As you might notice, the 3D points provided by the POC aren't perfect. There will always be a margin of error. This is for 2 reasons. First, if the feature points are on the same or similar planes, the essential matrix becomes less accurate. This is because we aren't giving the computer nearly as much info about how point location changes with depth. The second reason is simply that it's impossible to create a perfect mathematical transformation that will apply to all points. It simply needs to be as accurate as possible. How good is good enough depends on your project requirements.
